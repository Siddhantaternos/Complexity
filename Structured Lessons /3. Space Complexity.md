# `03_space_complexity/` — How memory *actually* grows

Space complexity exists because **time is not the only thing that kills programs**.
Sometimes code is fast… and still unusable.

Memory exhaustion doesn’t warn you politely.
It crashes. It corrupts state. It takes down systems.

Space complexity helps you predict **that failure** before it happens.

---

## First principle (read this twice)

Space complexity answers **one question only**:

> As input size `n` grows, how much **extra memory** does the algorithm consume?

Not total RAM.
Not system memory.
**Extra memory introduced by the algorithm itself.**

This distinction is critical.

---

## Two kinds of space (people mix these up constantly)

### 1) Input space (usually ignored)

Input space is the memory required to store the input itself.

Example:

```python
def process(arr):
    ...
```

If `arr` has `n` elements → input space = O(n)

We usually **do not count this**, because the input exists regardless of how we solve the problem.

Only include it **if the question explicitly asks**.

---

### 2) Auxiliary space (this is what matters)

Auxiliary space is memory created **by your algorithm**:

* variables
* temporary arrays
* hash tables
* recursion stack
* queues, stacks, heaps

When interviewers say “space complexity,”
they mean **auxiliary space**, unless stated otherwise.

If you forget this, your answer is wrong.

---

# Part 1 — `input_vs_auxiliary.py`

## Understanding what *counts* as space

### Constant auxiliary space — O(1)

```python
def swap(a, b):
    temp = a
    a = b
    b = temp
```

No matter how large the input gets:

* only a fixed number of variables exist

Auxiliary space → **O(1)**

This is called **in-place behavior**.

---

### Linear auxiliary space — O(n)

```python
def duplicate(arr):
    res = []
    for x in arr:
        res.append(x)
    return res
```

You created a new array that grows with input.

Auxiliary space → **O(n)**

Even though the loop is O(n) time, the *space* is also O(n).
Time and space are **independent dimensions**.

---

### Hash maps and sets

```python
seen = set()
for x in arr:
    seen.add(x)
```

Fast lookup, but memory grows with input.

Auxiliary space → **O(n)**

This is the classic trade:

* time improves
* space increases

Good engineers know when that trade is worth it.

# Part 2 — `recursion_stack.py`

## Recursion stack (the silent memory leak)

Recursion uses memory even if you don’t create arrays.

Why?
Because **each function call consumes stack space**.

Each stack frame stores:

* parameters
* local variables
* return address

---

### Linear recursion

```python
def factorial(n):
    if n == 0:
        return 1
    return n * factorial(n - 1)
```

Call depth = `n`

Auxiliary space → **O(n)**
Even though no data structure was created.

This is where many people answer “O(1)” and fail.

---

### Logarithmic recursion

```python
def binary_search(arr, l, r):
    if l > r:
        return -1
    mid = (l + r) // 2
    ...
```

Each call halves input.

Call depth ≈ log n

Auxiliary space → **O(log n)**

This is why divide-and-conquer is scalable in both time *and* space.

---

### Branching recursion (worst-case stack)

Even if recursion is exponential in time,
**stack depth might still be linear**.

That’s why:

* time complexity
* space complexity

must always be analyzed **separately**.

# Part 3 — `in_place_vs_extra_space.py`

## In-place algorithms (dangerously misunderstood)

An algorithm is **in-place** if:

* it modifies input directly
* uses constant auxiliary space

Examples:

* two-pointer techniques
* reversing arrays
* swapping elements

---

### Important nuance (interview gold)

Recursion can break in-place claims.

Example:

* QuickSort

Average case:

* in-place
* stack depth = O(log n)

Worst case:

* stack depth = O(n)

Correct answer:

> “In-place on average, not in the worst case.”

That one sentence separates juniors from seniors.

---

## Space complexity of common patterns

### Sliding window

Usually O(1) or O(k)

### Prefix sum

O(n) (extra array)

### BFS / DFS

O(n) (queue or stack)

### Dynamic Programming

* 1D DP → O(n)
* 2D DP → O(n²)
* Optimized DP → sometimes O(1)

Always ask:

> Can state be compressed?

---

## Hidden space costs people forget

These silently destroy space analysis:

* recursion stack
* slicing arrays (`arr[:]`)
* copying strings
* temporary objects
* list comprehensions creating new lists

Example trap:

```python
s = ""
for c in chars:
    s += c
```

Time → O(n²)
Space → O(n)

Looks innocent. Isn’t.

---

## Interview rule (use this sentence)

When asked space complexity, say:

> “Auxiliary space is O(X), excluding input.”

That sentence alone signals clarity.
